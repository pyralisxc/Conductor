# Owner Console Contract

## Purpose

The Owner Console is the unified visibility and command surface over Jarvis Conductor.

It is a projection over durable systems, not another source of truth.

## Mission Control

Prioritize:

1. Needs Founder / Owner Inbox
2. Project and Preview health
3. Warm conversational sessions
4. Active delegated workers
5. Waiting/event-bound work
6. Release readiness
7. Infrastructure/provider failures

Do not lead with raw logs or agent counts.

## Project Cockpit

Show main state, Preview state, integrated work, private work, warm sessions, delegated workers, Founder gates, audits, release candidate, and automation posture.

## Work Detail

Show Objective, Ambition, DevOS Stage, Operational State, Current Owner, Current Frontier, Evidence Appetite, branch/PR, Preview, proof, dependencies, and meaningful history.

Context-sensitive controls may include Continue, Pause, Resume, Take Over, Delegate, Reassign, Fresh Eyes, Rotate Chat, Hold Integration, Integrate Preview, Revert from Preview, Change Evidence Appetite, Escalate, Stop, and Retire.

## Conversational Session Console

Show attached work, session state, DevOS stage, frontier, human-input requirement, auto-continue setting, active delegations, and rotation reason if recommended.

Session states: Warm, Waiting, Human Gate, Rotation Candidate, Superseded, Retired.

Do not invent opaque AI session-health percentages.

## Founder Control Center

Every gate shows Decision, Why automation cannot decide it, Evidence, Meaningful choices, Consequences, and Resume behavior.

Actions: Choose direction, Discuss in Chat, Ask for more evidence, Defer, Reduce scope, Reject/retire.

## Preview Cockpit

Show exact Preview SHA, main→Preview delta, integrated work, product/system changes, CI and deployment health, audit state, physical acceptance state, changelog, deferred items, and discovered interactions.

## Release Control

Actions: Cut Release Candidate, Open exact deployment, Inspect changelog/evidence, Request audit, Remove/rework component, Approve exact SHA for main.

## Audit Center

Separate Proven defect / auto-repairing, Potential semantic issue / shaping needed, Consequential issue / human gate, and Insufficient evidence / proposed.

## Provider / Worker Console

Expose availability, health, capabilities, current work, permissions, and usage for ChatGPT, Work/Codex, API agents, GitHub Actions, local/Unity runners, DI, Vercel, and future providers.

## Cost / Usage

Track interactive sessions, worker runs, API spend/tokens, DI queries, Actions minutes, Vercel workflow/deployment usage, and local runner utilization where measurable.

## Explainability

Every significant automated action must answer:

- Why did Jarvis do this?
- What evidence supported it?
- What policy authorized it?
- What will happen next?
- How can the owner stop or override it?

## Owner-control maxim

> **The Owner Console should make the development organization legible without turning the owner into its scheduler.**
